Verified direct-connect findings

TMHP recognizes providers as direct trading partners and makes TIERS eligibility available through EDI/Safe Harbor. The July 28, 2026 Connectivity Guide documents HTTPS MIME multipart and SOAP/WSDL, CORE 2.2.0 and 4.0.0, and SFTP for file transfer. CORE 4.0 requires a TMHP-issued X.509 certificate; TLS 1.2 is documented. Safe Harbor is a connectivity standard/interface, not a requirement to buy a separate clearinghouse. Official Connectivity Guide, sections 1–5 and Appendix B.

The framework uses the guide's HTTPS 2.2 test address https://services-uat.tmhp.com/corerules/httpsrequest and production address https://services.tmhp.com/corerules/httpsrequest. These addresses were researched, not called. SOAP is an alternative; SFTP is relevant to native batch work. No specific PTHHS transaction-per-second allowance was established. Confirm new-enrollment protocol/version, rate, certificate and operational requirements with TMHP before choosing the production transport.

The November 6, 2024 companion guide supports real-time and batch 270/271. It specifies 5,000 transactions and 75 MB per batch, one ISA/GS per file, and one EQ for interactive inquiries. Medicaid ID plus last name or DOB is a documented matching path. Its ISA15 instruction uses P even in testing. Official 270/271 Companion Guide, sections 6–10.

Resolve before certification: the connectivity guide lists TIERS test receiver 617591011TIELT, while the companion's ISA08 table lists 617591011TIELP. Ask TMHP to specify CORE envelope, ISA08 and GS03 values for the chosen test route. Do not silently treat conflicting guide values as interchangeable.

The complete X12 implementation specification is licensed separately. The official X279 product covers the 270/271 implementation guide; an appropriate license and validated 005010X279A1 implementation are required for this project. No licensed TR3 was supplied or accessed during this task. X12 official product and licensing resource. Envelope work was also checked against CAQH CORE Connectivity Rule 2.2.0.

New-enrollment checklist

TMHP's current process assigns a test-only Submitter ID after required paperwork, allows up to 30 days for processing, and requires five error-free batches of 50 transactions per transaction type. Submit the successful batch IDs to the EDI Help Desk for production review; its page says transactions can begin within 24 hours after transition confirmation. Confirm additional real-time-specific testing. TMHP Get Started.

  1. Confirm existing status first. PTHHS enrollment owner should ask TMHP whether an account already exists and which provider/contracts and transaction methods it covers. HHAeXchange's display of eligibility does not prove that PTHHS has its own direct-submit approval.
  2. Prepare the application. Use the Trading Partner Application and Enrollment Form. Assemble legal entity/contact details, applicable provider identifiers, desired transaction scope, proprietary software information, authorized subcontractors and data-use/retention disclosures. Verify current fields before signing.
  3. Execute the applicable agreement. Have an authorized PTHHS signer review the EDI Trading Partner Agreement. Do not submit unsigned or unreviewed terms on behalf of the company.
  4. Determine LTC-specific paperwork. If PTHHS is enrolling as an LTC submitter, complete the LTC EDI Agreement for each applicable contract. The Submitter ID Linking Form applies when linking existing agreed LTC contracts to a new submitter. PAS service delivery alone does not establish the enrollment category.
  5. Confirm current submission channel. The current Get Started page gives TMHP, Attention EDI, PO Box 204270, Mail stop EDI-B14, Austin TX 78720-4270. Recheck the new electronic process below before submitting.
  6. Receive test access securely. Record the assigned submitter, approved provider scope, test endpoint, credential owner and expiry/rotation policy in approved systems. If required, arrange the certificate/CSR process. Never place credentials in GitHub issues, source, browser storage or this report.
  7. Complete acceptance and production approval. Use approved test fixtures and retain acceptance evidence privately. Obtain written confirmation for the actual method/transaction; then secure the owner's separate authorization for a production pilot.

Field availability and interpretation

The companion permits explicit active/inactive benefit evidence and conditional coverage/plan dates, managed-care plan references and repeated benefit loops. EB04 alone is insufficient to identify Medicaid: program and benefit context matter. REF18 identifies managed-care plan codes; DTP356/357 and plan dates require loop context. Missing data and AAA/acknowledgment errors do not establish inactivity. Companion Guide, response tables and examples.
